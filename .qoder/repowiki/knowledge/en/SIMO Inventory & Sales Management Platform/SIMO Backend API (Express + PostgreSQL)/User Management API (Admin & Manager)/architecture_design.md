Three-layer Express module mounted at `/api/users`:
- `routes/usuarios.routes.js` declares the HTTP surface (`POST /`, `GET /`, `GET /:id`, `PUT /:id`, `PATCH /:id/status`, `PATCH /:id/estado`) and composes the shared `verificarToken` + `verificarRol('ADMIN'|'GERENTE')` middleware from `../../middleware/authMiddleware` for authorization.
- `controllers/usuarios.controller.js` is the request handler layer: it validates inputs via local regex constants (`REGEX_CORREO`, `REGEX_ENTERO_POSITIVO`), hashes passwords with `bcrypt` (10 salt rounds), maps errors to JSON `{ error, message }` responses, and delegates persistence to the repository.
- `repositories/usuarios.repository.js` holds raw parameterized SQL against a PostgreSQL pool (`../config/db`). It exposes one function per operation; read queries use a shared `COLUMNAS_PUBLICAS` projection that never returns `password_hash`. Mutations (`actualizarUsuario`, `cambiarEstadoUsuario`) run inside explicit `BEGIN`/`COMMIT` transactions on a pooled client, acquire a PostgreSQL advisory lock `pg_advisory_xact_lock(hashtext('simo.administradores'))` before touching admin state, and enforce the invariant that at least one active admin remains — returning sentinel objects `{ noExiste, ultimoAdmin }` instead of throwing.
Dependency direction is strictly routes → controller → repository → db pool; the controller imports only the repository, and the repository imports only the DB config. Business rules (role existence checks, duplicate detection, last-admin protection) live in the repository so they are testable independently of HTTP.
