The top-level `backend/index.js` is the application entry point: it creates one Express app, installs global security middlewares (helmet, cors, json parser, `sanitizarXss`, `express-rate-limit` on `/api`), then mounts each child feature as an independent router via `app.use('/api/<domain>', <routes>)`. Domain routers (`src/routes/usuarios.routes`, `clientes.routes`, `inventario.routes`) follow a consistent three-layer split — routes → controller → repository — where repositories hold raw SQL against the shared `pg` pool exported from `db/index.js`. Authentication is centralized: `src/middleware/sanitizarXss.js` provides the global sanitizer, `src/config/jwt.js` holds the secret/expiry used by both the root `/api/auth/login` handler and the per-domain `authMiddleware`, and the root also owns the legacy `/api/products` endpoints plus `/api/auth/{login,logout}` (which writes to `jwt_blacklist`). Cross-cutting concerns (DB pool, JWT constants, XSS sanitizer) live outside any child module so all children depend on them rather than re-implementing them.
