Single `docker-compose.yml` defines five services under the project name `simo`: `db` (PostgreSQL 18-alpine with init scripts mounted from `../backend/db`, health-checked via `pg_isready`), `api` (built from `../backend`, connects as the minimal-privilege `simo_app` role, depends on db health), `frontend` (multi-stage Node 22 Alpine build of `../simoapp` using `deploy/frontend/Dockerfile`, exposes only port 3001 on loopback), `backup` (runs `respaldo.sh` inside a postgres image, mounts `./backup:/opt/backup:ro` and `./backups:/backups`), and `tunnel` (cloudflared, driven by `CLOUDFLARE_TUNNEL_TOKEN`). No published port binds a service to an external interface — all ports are prefixed with `127.0.0.1:` so internet access flows exclusively through the Cloudflare tunnel. The backup service is split into two shell scripts: `respaldo.sh` performs atomic `pg_dump` + `pg_restore --list` verification with `.tmp` rename semantics and daily retention cleanup; `restaurar.sh` restores into a single transaction, optionally drops/recreates schemas when `SIMO_REEMPLAZAR=si`, and refuses Neon targets unless `SIMO_CONFIRMAR_NEON=si`. Configuration is centralized in `deploy/.env.example`, which documents every variable and its production/default value.
